## Replacement boundary

- `/api/auth/*` keeps the existing Supabase email/password, verification PKCE, recovery, refresh and logout flows. Supabase access/refresh cookies stay HttpOnly, Secure, SameSite=Lax, host-only; mutations require the exact origin `https://love-live-myoko.com`. No customer credentials, bearer tokens or personal account records enter the static export.
- The single Finder inventory endpoint is `GET /api/property-finder/properties`. Every request requires `FINDER_AUTH_ENABLED=enabled`, a valid asymmetric Supabase JWT from the fixed project issuer, signed user/session IDs and a fresh version-2 private account snapshot. Banned, deleted, unverified, inactive, revoked or expired accounts/sessions fail closed. Headers, query parameters and JWT/user metadata cannot grant roles or entitlements.
- The application ignores Cloudflare Access assertions, authenticated-email headers and `CF_Authorization` cookies as credentials. They neither grant permission nor override a valid Supabase identity. A forged explicit Authorization bearer token still fails, even if another cookie or Access credential is present.
- Administrators receive all currently defined Finder permissions without a membership or payment, independently of `FINDER_CUSTOMER_ACCESS`. They still require a verified active account/live session. Existing property eligibility, source restrictions, restricted reader/Hyperdrive/TLS and RLS remain unchanged; administrator application access does not grant SQL/admin/crawler credentials.
- Customers require their real paid, active membership with valid dates, no revocation and the permission for the server-selected operation. Basic permits listings/search; Premium additionally permits the planned saved/map/refund-review capabilities. The actual Premium endpoints/features are not implemented by this cutover. **`FINDER_CUSTOMER_ACCESS=disabled` continues to deny all customer listing access**, including real paid rows, until billing is separately implemented, tested and approved.
- APIs disable browser/CDN caching and vary by Cookie/Authorization. There is no new public data endpoint, browser Supabase database client or static property inventory. The public Directus property pages stay public. Once the edge gate is removed, the search HTML may return a generic login shell to an anonymous browser; its API must return no property data.
